LESS FOREVER. MORE NOW.

A clear note
on privacy.

Ephemeral describes the lifetime of a message on this board. It is not a promise of secrecy, anonymity against every observer, or physical erasure of every copy.

Updated 5 November 2026

Public rooms and private invitations

Public room names provide no access control. Private event IDs require a separate random read capability. Anyone holding an invitation can join. Only explicitly listed public events appear in discovery; private rooms never do. Managed event IDs fail closed after expiration or restart.

What optional E2EE protects

For an encrypted private event, message text, replies and poll questions/options are encrypted in your browser using AES-256-GCM with a fresh 96-bit IV and room/message-type/parent/option-count authenticated data. The server receives ciphertext, not the content encryption key. Ordinary private rooms without encryption still expose message text to the server.

Invitations carry read and encryption keys in the URL fragment, which is not sent in HTTP requests. The app removes that fragment from the address bar after reading it. Sharing or copying the invitation grants access to its holder. Owner/moderator keys are separate and are never included in participant invitations. There is no key recovery or participant revocation short of closing the event and creating a new one.

E2EE does not hide room names/topics, aliases, timing, participant session counts, reactions, votes or traffic metadata. It does not protect against a compromised browser, malicious origin JavaScript, copied invitations, screenshots, or a participant sharing decrypted text. Shared room keys do not verify authors or provide forward secrecy. This implementation has functional and cryptographic regression tests, not an independent cryptographic audit.

Expiration and application memory

Active content or ciphertext, room metadata, votes, reactions, hashed capabilities, presence and reports are held in server memory with explicit capacity limits. Message lifetime is 3–300 seconds. Replies cannot outlive their parent. Event closure/expiry removes all dependent state. Independent timers and sweeps remove expired records without relying on browser polling. Restarting drops all active state.

Aliases, anonymous voting and reports

An optional alias is public to room participants and is not identity-verified. Presence counts page sessions rather than people and expires after missed heartbeats. Poll and reaction selections use hashed random page tokens; a determined participant can create new tokens. Reports contain a reason and hashed reporter token, expire with their message, and are visible to authorized moderators. Avoid posting sensitive personal information.

Browser storage and local QR generation

Message text, drafts, encryption keys, invitations, local hidden-message choices and burn/moderator capabilities remain in page memory. The app does not save them in localStorage, sessionStorage or service-worker caches. Only theme, view, motion and language preferences are saved. QR generation happens locally with no remote image service. Clipboard managers, browser history outside the app and screenshots may retain copies you choose to make.

Infrastructure and limits of deletion

Traffic passes through Cloudflare and nginx. The application access log omits client IPs, query strings, bodies, cookies and capability headers. Error logs and upstream services may retain operational data under existing operator policies. HTTPS protects transport; it is distinct from optional content encryption. Expiry is not a guarantee of physical memory erasure, log deletion or removal of copies made by participants.

Room URLs and API responses carry noindex directives. Message contents and invitation secrets never enter social metadata or the sitemap. Search-engine directives are not authorization.
